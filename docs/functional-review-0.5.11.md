# 0.5.11 功能排查与修复

本次检查由连续 502 转发日志和应用内更新卡住触发，同时复查引擎生命周期、账号/配置、Responses/compact、SSE、工具修复、图片上传、文件链接、日志与两端更新流程。此文记录已验证的问题，不代表所有网络环境或第三方客户端行为都能被离线测试覆盖。

## 已确认问题

| 问题 | 证据 | 修复 |
| --- | --- | --- |
| 选择 H1 后仍协商 H2，首字节前连续失败 | 真实 CONNECT + TLS 测试在旧代码下出现 `bogus greeting` / `malformed HTTP response`；修复后冷/热父传输及复用请求通过 | 清除 H1 克隆传输继承的 H2 ALPN 与协议处理器，保留证书校验和独立 H2 能力 |
| 200 响应头让连续断流退避过早清零 | 合成 SSE 连续只发送心跳后 EOF，旧代码每次仅退避 2 秒 | 完整响应后再清零，验证 2/4/8/16/30 秒及成功后恢复 |
| 普通中文括号加文件引用丢字 | 同一输入的流式结果与完整重写结果不一致 | 保留真实正则匹配之前的前缀，再从匹配结束位置继续处理 |
| macOS 更新退出死锁 | 真实 AppKit + 合成引擎已结束，但主队列退出回调及超时任务均未执行，超过 13 秒仍不退出 | 取消首次系统退出，异步清理完成后重新退出；正常约 2 秒、无响应约 11 秒通过 |
| 更新失败可能失去旧版或长时间卡住 | 旧 macOS 脚本先删除旧版；Windows 尾分隔符将备份放在目标内部，正文读取缺少总超时 | 完整复制、同级备份、失败回滚/重启、持久失败日志，下载正文设置期限 |
| 更新与引擎/窗口事件竞争 | 迟到的 stopped/error 可撤销进度；并发 Windows Dispose 曾提前返回 | 状态守卫、防重复检查、共享退出任务，关闭后的异步结果不再安装 |

## 验证范围

- Go：全部 7 个包的 `go test -mod=vendor -race -count=1 ./...`，以及 `go vet`；新增传输、退避、引用与日志脱敏回归测试。
- 上游协议：`scripts/check_upstream.py`；原生 `internal/transportdiag` 保持逐文件一致，修复仅位于本地适配层。
- macOS：UI 契约、嵌入日志、真实 AppKit 退出测试；临时目录中执行实际更新脚本，覆盖成功、复制失败、替换失败、重启失败、旧进程不退出。另用真实 helper 和 LaunchServices 完成退出、替换及新程序重启的完整测试。均不操作用户安装的应用。
- Windows：本地交叉编译；Windows CI 执行实际 PowerShell 脚本故障测试、WinForms 预览和真实隔离引擎 smoke。交叉编译不作为 Windows 运行验证的替代。
- 实际网络：修复后的引擎通过既有 `127.0.0.1:6789` 代理完成一次 BPS probe，返回连通性验证通过，未修改 Codex 配置。

## 适用边界

- 旧版更新器不能在升级前获得新代码；从 0.5.10 升级卡住时需要手动替换一次。
- 更新失败日志位于临时 staging 目录的 `update.log`。操作系统权限/文件锁阻止回滚时，日志记录保留的备份路径；不得自动删除该备份。
- macOS 发行包为 ad-hoc 签名，无 Apple 公证。真实网络验证是单次成功，不承诺上游或代理永不发生短暂中断。
