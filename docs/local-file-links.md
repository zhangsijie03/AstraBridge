# 本地文件引用

## 为什么不能用 `file://`

AiMaMi 1.2.6 的 Markdown 链接点击处理只放行 `http://`、`https://`、`mailto:` 和 `tel:`。本地文件协议不会触发打开动作，所以直接把 Codex 的路径改写成 `file://` 仍然会显示成不可用文本。

## 星桥的处理流程

1. 从 Responses 的输出文本中识别 `【文件名:行号】 (<绝对路径:行号>)`。
2. 校验路径必须位于用户目录或临时目录，且解析后的目标必须是普通文件。
3. 拒绝敏感目录、凭据文件、证书、密钥和超过 32 MiB 的文件。
4. 为文件生成 24 小时有效的随机令牌，并输出 `http://127.0.0.1:<port>/v1/files/<token>` 链接。
5. 浏览器点击链接时，星桥只读返回该文件内容；不允许上传、写入、目录遍历或跨机器访问。

## 生命周期与限制

- 令牌只保存在星桥进程内存，最多保留 4096 个，星桥重启后全部失效。
- 文件端点只监听 `127.0.0.1`，拒绝其它 Host 和带 Origin 的浏览器请求。
- Markdown、文本、JSON、YAML、TOML 及常见源代码按文本方式打开；其它类型按系统 MIME 类型以内联方式返回。
- 文件不存在、被替换、超出大小限制或令牌过期时返回 404。
- Responses 的 `output_text.annotations` 和 `logprobs` 字段仍会保留，结构化客户端不会丢失 `file_citation` 元数据。

## 排查

如果 AiMaMi 中仍只看到路径，先确认点击文本中已经出现 `http://127.0.0.1:<port>/v1/files/`。如果没有，说明客户端收到的不是星桥处理后的 Responses 输出；如果有但浏览器打不开，检查星桥是否仍在运行、端口是否被占用，以及本机浏览器是否能访问 `http://127.0.0.1:<port>/v1/files/<token>`。
