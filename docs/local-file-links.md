# 本地文件引用

## 为什么不能用 `file://`

AiMaMi 1.2.6 的 Markdown 链接点击处理只放行 `http://`、`https://`、`mailto:` 和 `tel:`。本地文件协议不会触发打开动作，所以直接把 Codex 的路径改写成 `file://` 仍然会显示成不可用文本。

## 星桥的处理流程

1. 从 Responses 的普通输出文本中识别 `【文件名:行号】 (<绝对路径:行号>)`，兼容尖括号内外围空格、Tab 和换行。
2. 校验路径必须位于用户目录或临时目录，且解析后的目标必须是普通文件。
3. 仅允许文档、文本、代码、常见图片和 PDF 扩展名；拒绝敏感目录、凭据文件、证书、密钥和超过 32 MiB 的文件。
4. 将授权绑定到规范化路径及发放时的文件身份，生成 24 小时有效的随机令牌，并输出 `http://127.0.0.1:<port>/v1/files/<token>` 链接。
5. 浏览器点击链接时，通过目录句柄逐级打开文件，核对文件身份并拒绝后来替换的文件或符号链接；校验后只读返回内容，不允许上传、写入、目录遍历或跨机器访问。

## 生命周期与限制

- 令牌只保存在星桥进程内存，最多保留 4096 个，星桥重启后全部失效。
- 文件端点只监听 `127.0.0.1`，拒绝其它 Host 和带 Origin 的浏览器请求。
- Markdown、文本、JSON、YAML、TOML 及常见源代码按文本方式打开；常见图片和 PDF 按安全的内联 MIME 类型返回；其它类型不生成本地文件链接。
- 文件不存在、被替换、超出大小限制或令牌过期时返回 404。
- Responses 的 `output_text.annotations` 和 `logprobs` 字段仍会保留，结构化客户端不会丢失 `file_citation` 元数据。
- 普通中文括号按正文透传；未完成的引用在输出结束或失败前补发为文本增量，避免只读取 delta 的客户端丢字。
- 请求指定 `text.format` 为 `json_object` 或 `json_schema` 时，保留原生校验后的文本，不改写文件引用、不生成文件授权，避免破坏 JSON 转义或 Schema 约束；流式增量与终态遵循同一规则。

## 排查

如果 AiMaMi 中仍只看到路径，先确认请求是否指定结构化 JSON 输出、引用语法是否匹配、文件是否存在且属于允许的类型和路径。普通文本中通过校验的引用应出现 `http://127.0.0.1:<port>/v1/files/`；如果已有链接但浏览器打不开，检查星桥是否仍在运行、链接是否过期，以及文件是否被替换。
