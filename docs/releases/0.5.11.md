# AstraBridge · 星桥 0.5.11

修复 0.5.9 / 0.5.10 通过本地代理连续出现 502、重新连接的问题，以及 macOS 更新准备完成后无法退出的阻塞。

## 连接与文件

- 修正 HTTP/1.1 传输仍通过 TLS ALPN 宣告 HTTP/2 的配置冲突；本地 CONNECT + TLS 回归测试覆盖冷启动、连接复用及原 HTTP/2 连接。
- 连续断流时按 2、4、8、16、30 秒累计退避，只在响应完整完成后清零。
- 日志增加实际协商协议、连接阶段与错误分类，不记录凭据、请求内容或原始网络错误。
- 修复中文普通括号紧邻文件引用时，流式重写丢字或破坏 UTF-8 的问题。

## 应用内更新

- macOS 先异步关闭引擎，再退出 App，避免 AppKit 的退出等待阻塞回调；正常退出及无响应兜底均增加真实 AppKit 测试。
- macOS / Windows 校验和解压在后台执行，更新期间迟到的引擎状态不会覆盖进度或重新启用按钮。
- 更新前检查安装权限，完整复制新包后才移动旧版；复制、替换或重启失败时保留/恢复旧版并记录 update.log。
- 修复 Windows 安装路径尾分隔符导致的目录替换失败，避免更新器工作目录占用安装目录，并合并并发引擎退出请求。
- 防止重复检查/安装；Windows 下载正文增加超时，避免只有响应头成功却持续等待正文。

## 升级提示

0.5.10 的更新过程仍由旧版代码执行，无法在安装前获得本次退出修复。若旧版卡在更新，请退出旧版后手动解压并替换应用一次。安装 0.5.11 后，后续更新使用修复后的流程。两个平台都应将应用放在用户可写的独立目录内。

## 验证

- Go 全量 race 测试、vet、上游源码校验。
- macOS 原生界面、真实退出、更新成功及失败恢复测试、应用离线 smoke 与签名验证。
- Windows 原生构建、界面/引擎离线 smoke 与 PowerShell 更新故障测试由 Windows CI 验证。
- 已通过现有本地代理完成一次真实 BPS 连通性验证。
