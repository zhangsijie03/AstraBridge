# AstraBridge · 星桥 0.5.3

本版本修复 BPS 流内限流后，客户端在冷却期重试仍反复请求上游的问题。

## 更新内容

- 按 Sub2API v2.9.3 的 BPS 规则增加账号级冷却：优先使用有效的 Retry-After，缺省 5 秒，范围 1–7200 秒；并发更新保留更长的截止时间。
- 增加宿主层流内限流识别，覆盖 HTTP 200 后的 error、response.failed、response.incomplete 中明确的 rate_limit_exceeded。此项是针对原生 HTTP 429 分支之外场景的补充，原生协议文件不变。
- 图片上传、生成、工具纠错及连接测试共享冷却；停止并重新开启中转不清空同一引擎进程的冷却。换账号独立处理，刷新同一账号令牌不会绕过冷却。
- 冷却中的新请求在本地返回 HTTP 429、rate_limit_error 和 Retry-After，不读取大请求体或再次上传图片。
- macOS 和 Windows 界面显示“最近请求被限流”。转发日志区分上游限流与本地拦截，显示本地冷却截止时间。
- 已开始的流保留原生失败事件，不伪造完成、不重放已有内容。

## 升级与边界

先退出旧版，完整解压新版。仍需手动启动中转，模型保持 gpt-6-astra，已有配置继续使用。

冷却结束只表示本地允许再次尝试，不保证上游配额已经恢复。上游没有提供恢复时间时，5 秒是原生默认回避值，不是实际配额重置时间。正在上游执行的其他请求不会被主动中断。退出应用会清空进程内冷却。

本次验证使用合成账号及本机模拟上游，未发送真实 BPS 测试。macOS 包为 ad-hoc 签名；Windows 交叉编译不替代 Windows 实机启动验证。
