# AstraBridge · 星桥 0.5.12

修复第二轮审查确认的四项功能缺陷，以及 macOS 协议来源显示过期的问题。

## 更新与文件保护

- Windows 更新只替换新发行包包含的文件，保留安装目录中的额外配置、日志和个人文件；安装前完整备份旧文件，失败时逐项回滚。
- 安装路径出现文件/目录冲突或符号链接时停止更新；回滚失败会保留备份位置和诊断日志，避免继续删除恢复材料。
- 本地文件链接绑定发放时的文件身份；打开时通过目录句柄核验路径，对原路径与解析后的目标执行敏感路径检查。文件或父目录被替换成符号链接后，旧链接返回 404。

## 文本、代理与来源

- 普通中文括号（如 `【注意】(仅供参考)`）不再阻塞后续流式正文；未闭合的尾部文本在完成、失败或断流前补发，保留输出索引并同步调整事件序号。
- macOS 更新器根据代理协议选择默认端口：HTTP 为 80，SOCKS5 为 1080；显式端口正常沿用，SOCKS5 / SOCKS5H 不再被当作 HTTP 代理。不支持的配置明确报错。
- macOS“关于”和“协议来源”读取包内来源清单，显示真实的 Sub2API v2.9.4 与固定提交，来源链接指向同一提交。

## 升级提示

**Windows 0.5.11 及更早版本的升级过程仍由旧更新器执行，无法提前获得本次文件保护修复。若安装目录中有个人文件，请先备份，退出旧版后手动解压新包并覆盖程序文件一次，不要删除整个安装目录。** 安装 0.5.12 后，后续应用内更新使用逐文件替换和保留用户文件的流程。

macOS 0.5.11 可直接在应用内检查更新并升级。安装目录需要可写；macOS 0.5.10 若卡在旧版退出流程，仍需手动替换一次。

## 验证范围

- Go 全量 race 测试、vet、上游源码逐文件校验。
- 新增文件替换/敏感符号链接/父目录替换、HEAD/Range、引用分段与多输出、结束及断流正文完整性测试。
- macOS 代理默认端口和无效配置测试，真实 URLSession 的本地 HTTP CONNECT / SOCKS5 握手，以及包内来源清单测试。
- macOS UI 契约、日志交互、真实 AppKit 正常退出/超时兜底/更新替换后重启、离线 smoke 和签名检查。
- Windows 成功安装、复制失败、备份失败、安装中途失败、重启失败、回滚失败、旧进程未退出和目录冲突测试；两个平台通过发布 CI 后才上传安装包。

本轮使用临时目录和合成数据，没有读取真实账号或发送真实 BPS 请求。本次未扩展文件格式白名单，Office 文件仍不生成本地下载链接。
