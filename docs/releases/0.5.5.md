# AstraBridge · 星桥 0.5.5

整合自 v0.5.2 以来的协议对齐、限流处理、连接诊断与主页面日志改进。macOS Apple Silicon 和 Windows x64 使用同一套 Go 引擎，统一发布。

## 主页面精简日志

- 转发日志常驻主窗口下方，窗口加高并支持调整大小。
- 每个请求只占一行，同一请求的进展持续更新原行。
- 首列绿色 ✓ 表示完整完成，红色 ✕ 表示失败，橙色 … 表示进行中，灰色 — 表示取消或停止后未确认完成。
- 表格显示时间、请求编号、耗时和简要状态；悬停查看完整详情，保留复制、导出和自动滚动控制。
- 关闭自动滚动后保留选中请求和阅读位置；停止中转后保留历史，不将未完成请求标记为成功。
- 表格最多保留 1000 个请求；复制／导出保留最近 1000 条完整事件。日志仅在当前应用会话中保留，退出不会自动落盘。

## 连接与错误处理

- 在原生 15 秒注释心跳之外补充完整 SSE 保活事件，适配按事件计算空闲超时的客户端。保活不生成模型内容或工具调用，不计作上游业务进度；取消与 60 分钟总超时仍有效。
- model_not_found、model_not_found_error 和 basispoints_model_access_changed 显示明确的“上游模型暂不可用”，保留安全的错误码及真实状态，不自动重放请求或切换模型。
- HTTP 200 中的流内失败仍显示失败，并分别记录实际 HTTP 状态和错误分类状态。
- 对照 Sub2API v2.9.6 未发现这两类报错的专门恢复补丁。事件级保活属于星桥兼容调整；协议内核继续锁定经校验的 Sub2API v2.9.4，不宣称本地能够恢复上游模型权限。

## 原生协议与限流

- 协议对齐 Sub2API v2.9.4 固定提交：59 个原生协议文件原样同步，2 个文件登记为星桥本地适配，另保留 1 个明确标注的图片辅助代码提取文件；3 个传输诊断文件继续原样同步。
- 采用原生 UpstreamFailure 分类，统一识别限流、鉴权、权限、请求错误、上游取消及服务器错误。上游取消后及时停止读取。
- 生成、图片上传、工具纠错和连接测试共享账号级 BPS 冷却：有效 Retry-After 优先，缺省暂缓 5 秒，本地范围 1–7200 秒。同一引擎停止／启动保留冷却，退出后清空。
- 冷却期的新请求在本地明确返回 429，不重复上传图片或请求上游。日志展示经校验的等待及额度提示；默认 5 秒不代表上游配额恢复时间。
- 同步图片附件引用修复，仅发送上游支持的 type/file_id 字段。

## 升级与验证边界

先退出旧版，再完整解压新版。Windows 请保留 EXE 旁的 engine 与随包文件；已有配置继续使用。每次打开仍需手动启动中转，固定模型为 gpt-6-astra。

发布流程在 macOS、Windows runner 分别执行 Go 回归及竞态检查、构建和离线 smoke 验证；macOS 额外检查精简日志布局与交互，Windows 运行实际 WinForms 日志用例。全部请求测试使用合成凭据和模拟上游，不代表已验证真实 BPS 权限或全部 AiMaMi 路由、DPI 与网络环境。

保活在上游成功响应头之后生效。若中间路由过滤未知 SSE 事件、等待响应头时超时或网络实际断开，仍需进一步排查。上游模型不可用可能继续返回 404，本地不能绕过权限或限额。

macOS 使用 ad-hoc 签名，未经 Apple 公证；Windows 未做商业代码签名。提供两平台 ZIP 和 SHA256SUMS.txt。
