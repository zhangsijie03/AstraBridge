# 星桥内置原生图片上传

## 范围

AstraBridge 0.4.0 在现有 AiMaMi → 星桥 → BPS 链路内，自动将用户消息和 function/custom 工具结果中的 `input_image.image_url=data:image/...;base64,...` 上传为原生附件。固定模型仍为 `gpt-6-astra`，沿用既有本地地址、Key、账号读取和代理。图片不会发布到本机 HTTP 路由或第三方图床，不读请求里的本地文件路径。

## 流程

1. 本地 API Key 鉴权、请求并发与资源预算准入。
2. 读取本次服务端账号，校验固定模型与完整 JSON 请求。
3. 上游 `PrepareNativeImages` 校验全部图片，暂置 `file-preflight`；调用原有 `Prepare` 校验工具和历史，失败时零上传。
4. 使用同一 HTTP 客户端/代理、账号及凭据向固定 `https://bps.openai.com/basispoints/api/attachments` 发送 multipart `file`。每次最多 60 秒，禁止重定向。
5. 校验 `openai_file_id`，关闭上传响应，再把真实附件 ID 转换为 BPS Responses 请求。任何上传失败即终止，不重试、不换账号、不回退。

## 限制与缓存

- PNG/JPEG/GIF/WebP，单图 20 MiB、20 张/请求、合计解码后 32 MiB、每图 64 Mi 像素；HTTP JSON 最多 64 MiB。
- 请求体按 8 倍预估占用、最小 1 MiB 原文额度，最多 512 MiB 预算；未知长度预留整个请求上限。最多 8 条在途请求，预算不足在读体前返回 503，带 Retry-After。
- 附件上传与 Responses 均受客户端取消和 20 分钟总超时约束。附件缓存复用上游实现，存储最多 512 条 ID 元数据，上传起 30 分钟失效且读取不续期；不保存原图文件。
- 缓存作用域哈希含账号 ID、凭据、本地 Key 及线程。无线程时使用请求唯一作用域，不跨请求复用；凭据更新后重新上传。
- 上传错误保留适当 HTTP 状态，仅返回固定提示，不回显正文、令牌或附件 ID。429 不改账号状态。
- 本地缓存的到期时间不决定 BPS 上游保存图片的期限。

## 源码边界

原有 v2.8.11 的 21 个非图片协议文件保留。上游固定提交 `26b324b44c80929e5f86aeb36e09996423c4a5c0` 的 4 个图片/附件文件原样使用，共享校验依赖单独提取。宿主层负责 HTTP 与资源准入。每项都有锁定哈希，不跟随 production 分支自动升级。

## 验证

使用合成 PNG 和本机假上游验证 multipart 内容、消息/工具截图、流式/非流式、compact、去重、凭据与线程隔离、错误、取消和预算回收。上游原版附件测试覆盖缓存过期、并发合并、容量及像素/字节上限。真实账号的附件权限、真实上传和视觉回答未验证；开发过程不发送真实凭据。
