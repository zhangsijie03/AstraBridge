# SSE 空闲超时、模型 404 与精简日志审查

核查日期：2026-09-30。此文记录本地测试候选的原始核查结果；相关改动整合进入 v0.5.6，后续平台验证结果以对应发布流程为准。

## 上游依据

- 检查时最新发布为 [Sub2API v2.9.6](https://github.com/ranxi2001/sub2api/releases/tag/v2.9.6)，发布时间 2026-09-30 08:55:21 UTC。
- 发布标签解析到提交 9f7d96be367e795bd76e1f45c82bd5d4c563e0fa。
- 原生 [openai_excel_bps.go](https://github.com/ranxi2001/sub2api/blob/9f7d96be367e795bd76e1f45c82bd5d4c563e0fa/backend/internal/service/openai_excel_bps.go) 约 550–615 行保留上游拒绝状态，单独识别 basispoints_model_access_changed；约 695–711 行仍采用 15 秒 SSE 注释心跳。
- 原生 openai_compact_sse_keepalive.go 也说明注释被 EventSource 解析器忽略；其中的延迟写入及互斥保护解决连接写入问题，并不让注释变成数据事件。
- 官方 [Codex SSE 实现](https://github.com/openai/codex/blob/main/codex-rs/codex-api/src/sse/responses.rs) 在等待下一个解析后的 SSE 事件时应用空闲超时。检查时，未知事件在解析后被忽略，仍能结束本次等待。
- 官方 [Codex 配置参考](https://developers.openai.com/codex/config-reference/) 提供模型提供方的 stream_idle_timeout_ms 配置。本轮没有修改用户的 Codex 配置。

未发现 v2.9.6 对这两个具体报错提供可直接移植的专门恢复方案。协议内核仍保持现有 v2.9.4 锁定；没有为本轮 UI/连接改动无差别升级原生文件。

## 图 1：idle timeout waiting for SSE

截图能确认客户端等待 SSE 事件超时，不能仅凭截图证明所有断线都由星桥心跳引起。已确认的兼容缺口是：注释心跳只能维持字节连接，不会产生 EventSource 数据事件。

在星桥网关的完整事件写入点保留原有注释，并增加 event: keepalive / data: {"type":"keepalive"}。初始帧与后续每 15 秒心跳使用同一机制；它不生成模型文本、工具调用或 Responses 生命周期事件，不刷新上游字节/静默计数，不计作客户端业务事件。

这是**星桥的客户端兼容调整**，不是声称从 Sub2API 移植了一个不存在的修复。原生协议转换与纠错策略没有改变。取消会结束上游请求，60 分钟总截止时间仍生效，也不增加自动重放。

边界：保活在收到上游成功响应头并进入转发后生效；不能修复响应头等待、真正断网或其它路由主动终止。如果 AiMaMi 丢弃未知数据事件，最终客户端仍可能超时，需结合该段日志继续确认。此次没有使用真实凭据验证 AiMaMi → BPS 完整链路。

## 图 2：HTTP 404 / model_not_found

截图中的状态与错误码来自 BPS 上游，不是星桥本地返回“路由不存在”。网关已验证输入模型为 gpt-6-astra，测试也确认发送给上游的模型值不变。

同原生拒绝处理边界，保持 HTTP 状态，不自动换模型、重放请求或禁用整个账号。针对 model_not_found、model_not_found_error 和 basispoints_model_access_changed，增加明确的“上游模型暂不可用”提示，并保留安全的上游错误码/类型。

HTTP 200 流中的模型失败仍按失败处理，日志同时保留实际 HTTP 200 与分类状态 404。其它 404 不误归因为模型不可用。原始上游错误消息可能回显正文或凭据，不直接写入客户端提示或日志。

本地调整改善分类和排查，**不能恢复上游模型权限或保证模型可用性**。可稍后手动重试，持续出现需核实当前账号的 BPS 模型权限；单次 model_not_found 不足以推断永久失权或登录失效。

## 主页面精简日志

macOS 使用 NSTableView，Windows 使用 DataGridView；同一请求持续更新一行。

| 首列 | 含义 |
| --- | --- |
| 绿色 ✓ | 本次响应完整返回客户端 |
| 红色 ✕ | 失败，包括 HTTP 200 中的流内错误 |
| 橙色 … | 准备、连接、等待、接收或工具纠错中 |
| 灰色 — | 客户端取消，或停止中转时尚未确认完成 |

其余列仅显示时间、请求编号、耗时、精简状态。悬停查看完整最新详情；复制/导出仍保留最近 1000 条完整事件。表格最多 1000 个请求，优先淘汰终止行，暂停滚动时保留选中请求与顶部请求。停止不清除历史，也不把未完成行变成成功。
